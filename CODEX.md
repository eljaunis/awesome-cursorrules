# Using this repository with OpenAI Codex

This repository primarily contains Cursor `.mdc` rules. Codex Agent Skills use `SKILL.md` packages instead, so loading every `.mdc` file directly as global instructions would be both incompatible and unsafe: many rules target mutually exclusive frameworks or versions.

The included installer migrates each `.mdc` rule into an individually discoverable Codex skill and installs a routing skill that tells Codex to inspect the current repository and select only the narrowest matching rules.

## Windows / PowerShell

From a clone of this repository:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install-codex-skills.ps1
```

Or without keeping a clone locally:

```powershell
$u = 'https://raw.githubusercontent.com/eljaunis/awesome-cursorrules/main/scripts/install-codex-skills.ps1'
Invoke-WebRequest $u -OutFile "$env:TEMP\install-codex-skills.ps1"
powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-codex-skills.ps1"
```

The installer uses `$env:CODEX_HOME` when defined; otherwise it uses `~/.codex`. It writes migrated skills under `~/.codex/skills/` and adds a small routing block to `~/AGENTS.md` so Codex consistently considers the router for software-engineering tasks.

Restart Codex completely after installation and start a new thread so skill discovery is refreshed.

### Refresh after this repository changes

Run the installer again. Generated `cursorrule-*` skills are refreshed. Existing hand-authored skills that were not generated by this installer are left alone unless `-Force` is supplied.

```powershell
.\scripts\install-codex-skills.ps1
```

### Options

```powershell
# Install into an alternate Codex home
.\scripts\install-codex-skills.ps1 -CodexHome 'D:\codex-home'

# Do not modify ~/AGENTS.md
.\scripts\install-codex-skills.ps1 -NoGlobalAgents

# Replace colliding non-generated skills too
.\scripts\install-codex-skills.ps1 -Force
```

## What gets installed

For each `rules/*.mdc`, the installer creates:

```text
~/.codex/skills/cursorrule-<rule-name>/SKILL.md
```

Each migrated skill keeps the original rule body while translating the Cursor metadata into a Codex-oriented activation description. It also adds explicit selection discipline so unrelated stacks are not applied.

The installer additionally creates:

```text
~/.codex/skills/awesome-cursorrules-router/SKILL.md
```

The router instructs Codex to identify the actual repository stack first and then use only relevant rules. Repository-local `AGENTS.md`, explicit user instructions, actual dependency versions, tests, and current authoritative documentation take precedence over these generic migrated rules.

## Why not make every rule global?

The collection contains framework-specific and version-specific rules that can conflict—for example multiple generations of Next.js, React, Angular, Vue, databases, testing frameworks, and deployment platforms. Installing all of their contents into one global `AGENTS.md` would cause Codex to receive contradictory instructions on every task.

Agent Skills are a better fit: all guidance is available, but Codex can select it according to the task instead of applying everything simultaneously.
